## 本地开发：刷新失败保留与地形空值修复（0.2.11）

已有结果时，新一批天气暂存到全部点成功且有共同有效时次后统一替换。失败、限流、超时或取消继续展示上一批天气，显示旧结果读取时间和本次状态；不会把新旧天气点混为一批。首次分析仍逐点显示进度与已完成结果。切换来源、模式或路线仍清空不兼容结果。保留旧天气时不自动启动本次地形和GFS阶段；单独GFS补查仍可使用。

地形接口数字解析拒绝空值、空字符串、布尔值、非有限数值和非十进制数字格式；真正的数值0米保留。地形缓存与天气点回填统一使用七位坐标键，缺测不记为海平面。

## 本地开发：刷新与缺测诊断（0.2.11）

「重新分析」跳过插件五分钟天气缓存，重新调用主来源和启用的 GFS 补查；「补查／重试 GFS」也跳过补查缓存。普通查看仍复用缓存。Open-Meteo 强制刷新同时禁用浏览器 HTTP 缓存；Windy 通过现有接口重新请求，不能保证其内部缓存或模型已经更新。地形缓存独立保留，并发、限流与取消规则仍适用。

Open-Meteo 来源详情及可复制诊断新增字段未返回、空值、时次数组缺项、格式异常、单位不匹配、无效数值和范围异常的计数与涉及字段。不包含原始天气值。计数包含地表以下原始层，与可用于视线的高度层数量不同；查询高度低于地表、超出有效范围或相邻层缺口仍分别说明，不以零值替代缺测。

云区位置详情的估算界限按百米（英制五百英尺）取整，小于该尺度的垂直差显示「不足」；显示附近已返回高度层最大间距。取整是阅读尺度，不代表百米精度；真实峰顶海拔、原始层高度及计算值不变。

## 本地开发：预报时段概览与路线保存分享（0.2.11）

### 预报时段概览

路线有两个点且启用机位—雪山视线检查后，在全屏剖面展开「预报时段概览」。概览仅使用主来源已下载的数据，与当前时次面板使用同一判断逻辑；不发新的天气请求，不混入GFS独立补充。按北京时间分日期列出云层相交信号、高湿、未知和有效样本数，点选时次可切换主图。信号与资料不完整可能出现在同一个点，数量不是概率或可见面积，未知不能当作无云。

计算只在展开后开始，每8个时次让出界面响应；关闭区域、改路线/海拔/来源、销毁组件会拒绝旧计算结果。按日显示时次，避免几百行一次占满界面。Open-Meteo图表的时次选择不会被Windy地图的时间范围反向覆盖。

### 我的路线与文件分享

「我的路线·保存与分享」位于选点区和全屏剖面中。先保存当前路线，也可直接导出当前路线文件；名称可留空，默认起点→终点。同名同设置的重复保存会跳过。保存内容包括WGS-84点坐标、点名/命名类型、各点校正海拔、机位/目标视线海拔校正、视点离地高度、绿色查询高度、天气来源/模式及采样设置。预报时次和旧天气不保存，使用路线后仍需分析最新天气。

本浏览器最多保存50条路线，每条2～100点，列表支持搜索、10条分页、删除与本次打开期间撤销删除。使用路线会替换当前草稿并取消旧分析，恢复设置、定位地图并滚动到分析区域；可先保存当前草稿。

分享方法：导出当前路线或全部路线为JSON，手动发给朋友；朋友在插件中导入后点「使用此路线」再分析。文件是UTF-8、WGS-84、海拔单位米，不包含天气、缓存、账号凭据或API密钥。本地路线与地点收藏分开保存，不跨浏览器/设备自动同步。

导入最多2MB，先校验全部路线、经纬度/海拔范围/设置/格式版本，再追加；不覆盖已有路线或当前分析，相同路线跳过。不自动猜测或转换其他坐标系。不导入独立网页版的其他文件格式。

本轮构建、TypeScript和diff检查通过，未新增/运行自动化测试；真实页面操作、手机文件导入导出和概览性能仍待验收，按用户要求暂缓浏览器验收。未提交/推送/发布，线上仍0.2.10，独立网页版未修改。


## 本地开发：云区相对视线位置（0.2.11）

启用机位—雪山视线检查后，面板新增逐点云区位置：上方、下方、上下分布、云量或估算云区相交、高湿可能云区相交、资料不足、已返回层未发现云区信号。模式云带和高湿可能云区分开列出；Open-Meteo EC/ICON 的 API 湿度推算云带不作为独立湿度证据。

点击「逐点云层相对视线」可切换采样点；图上对应白色视线点放大并用青色描边，原绿色查询高度线不移动。所选点列出视线高度、云区上下界估计及与相关层界的估计高度差。只有相关边界有相邻有效层支持时才判断上方/下方；边界未确定或视线云湿缺测会保留未知。数据间隔两端有值也不等于区间已连续采样。

GFS 单独补充同样给出所选点位置；若只有两侧代表时次的保守云湿值，没有精确匹配帧，则位置保持资料不足，不把不同时次的云带拼成确定位置。云量多少与遮挡概率不同，不输出肯定可见结论。

构建、TypeScript和diff检查通过，未运行自动化测试。按用户最新指令继续开发，真实页面验收延后；此前Chrome连接报nodeRepl.fetch request failed，内置浏览器打开尝试超时，均不算页面验收。线上仍0.2.10，本地未提交/推送/发布，独立网页版未修改。


## 本地改进：加载、有效数据、来源与视线覆盖（0.2.11）

1. 先选择天气来源、模式和请求间隔，再点「分析并查看路线剖面」。选择设置不发请求；切换预报时次复用已取得的数据。来源、模式、补查开关及请求间隔保存在各自浏览器；插件不再被 Windy 地图模式切换强制改变选择。
2. 主天气完成就打开剖面，沿途地形随后补齐；地形读取有进度和取消。GFS 在主流程结束后独立补查，可单独取消或重试，不拖住已完成主结果。所有请求仍共享三请求并发限制。取消、来源/坐标变化后旧响应不能回写。
3. GFS 是否需要补查按当前时次与查询/视线高度判断，不因十五天中某个无关时次缺测就触发。补查仅为独立参考，主来源数值不被覆盖。
4. 有高度但所有天气值为空的帧不作为有效时次；零温度、零风、零云和零降水仍是有效值。只含地面天气时仍可显示地面数据，但不计为有垂直天气。空帧保留用于诊断，摘要按实际时间匹配原始帧。
5. 视线面板列出云量、湿度有效样本数和资料不完整的距离段。区段标签只说明两端样本，不宣称区间被连续直接采样；云量多少不能换算成遮挡概率。云信号点沿用主图云量色阶，估算云区/高湿、缺测和零云量分开。云量零而湿度缺测的点仍显示资料不完整。
6. 展开「模型网格」可查看官方网格/时间分辨率、实际模型格点中心（接口提供时）、当前温湿风云有效高度层及本机读取时间。IFS0.25°和GFS气压层约25千米，ICONGlobal约11千米；5千米路线采样不代表5千米天气精度。小时API序列不等于原始模型每小时更新。雾提示使用实际来源标签。

构建、TypeScript与diff检查通过。未新增或运行自动化测试；真实Windy页面跨域、加载先后、补查取消与选择记忆仍待验收。未提交、推送或发布，线上仍0.2.10；独立网页版未修改。

分辨率依据：[ECMWF](https://open-meteo.com/en/docs/ecmwf-api)、[ICON](https://open-meteo.com/en/docs/dwd-api)、[GFS](https://open-meteo.com/en/docs/gfs-api)。


## 0.2.10：可选天气来源与 EC／ICON

在顶部先选「天气来源」，再选「模式」：

| 来源 | ECMWF | ICON |
| --- | --- | --- |
| Windy | 当前 Windy ECMWF | 当前 Windy ICON |
| Open-Meteo | ECMWF IFS 0.25° 气压层 | ICON Global 气压层 |

Open-Meteo 作为主来源时，主路线图表、所选点垂直剖面、降水、雾提示和视线云层检查都使用选定模式；不调用 Windy 天气接口，也不自动混用其他模式。地图、收藏及沿线地形仍由 Windy 提供。EC 最多请求15天、ICON最多请求7天，仅显示实际返回时次；不外推缺测。Windy 模式仍可选择独立 GFS 缺测参考。

Open-Meteo EC 使用支持逐层数据的 IFS 0.25°，不是9km HRES；EC／ICON气压层云量由API根据湿度推算，与湿度不是独立证据。逐层露点由温湿度估算；模式地下层在解析时剔除，仍保留原始层序以拒绝跨缺层插值。完整云底、逐层能见度没有提供，地面能见度也可能缺测。起报时间未返回，小时接口序列包含时间插值。

切换来源或模式会取消旧任务、清空旧天气，分别缓存来源／模式／坐标／请求范围；同一轮结果不混用前一来源。真实 Windy 页面跨域与交互尚待验收。网页版未修改。

接口依据：[ECMWF](https://open-meteo.com/en/docs/ecmwf-api)、[ICON](https://open-meteo.com/en/docs/dwd-api)。


## 0.2.10：Windy 缺测的外部补充

路线分析默认启用 Open-Meteo GFS 补查，可取消勾选。补查会把分析点 WGS-84 坐标发送给 Open-Meteo；不发送 Windy 凭据。Windy 数据与零值保留，GFS 不写入原始 Windy 剖面，不延长已有 Windy 预报覆盖。

全屏剖面所选点下方显示「外部缺测补充」：查询高度的温湿风云、地面能见度和一小时雪水当量，明确标注来源与实际时次。视线面板展开「Open-Meteo GFS · 独立视线云层参考」查看沿线依据；不同模式不拼接成确定的无云结论。两侧有效时次间隔不超过三小时才取较大的云量、湿度，缺任意一侧保留未知。温度、风、地面能见度与雪水当量仅显示精确匹配时次。

仅在有效相邻气压高度层之间插值，不跨缺层、不使用模式地下层；完整云底、逐层能见度仍未提供。GFS 位势高度轴、小时接口时次与模式地形仍有模型限制。三个请求并发、20 秒补查超时、五分钟/96 份缓存；429 后暂停新补查一分钟。失败保留 Windy 证据，重新分析可重试。网络与 Windy CSP/CORS 能否允许外部请求尚需真实页面验收。

天气数据：[Open-Meteo](https://open-meteo.com/)（CC BY 4.0），[GFS 接口说明](https://open-meteo.com/en/docs/gfs-api)。独立网页版未修改。

## 开发和加载

1. 在项目目录运行 `npm install`。
2. 运行 `npm start` 并保持终端运行。开发服务器在 `https://127.0.0.1:9999` 提供 `dist/plugin.js`。如果提示 9999 端口已被占用，说明已有开发服务器在运行，直接使用它即可，不要再开第二个。

## 天气来源与缺测诊断

- 使用官方 SDK 点预报接口，请求 header、meteogram、airgram 和 sounding；云量及位势高度来自 meteogram／sounding／header，温风来自 airgram／sounding，逐层湿度来自 sounding。
- 空主时轴会使用实际返回的其他有效时轴，各字段仍按自己的时轴精确匹配，不借用其他时次。
- 云量或湿度未返回时检查官方弃用的兼容接口。不同起报、时间、气压或高度不混用，已有有效值（包括零）不覆盖。
- 展开逐点数据诊断复制摘要，可区分字段未返回、时次缺失、缺少有效高度和地形过滤；摘要不包含坐标或原始天气值。
- 只查询有效层间数据，不向地形以下、预报覆盖之外或层间缺口外推。地面能见度不代表高空透明度。

## 路线天气

- 切换到路线模式后，可按顺序点击地图，或输入经纬度添加起点、转折点和终点。大陆奥维坐标带 `g` 并自动转换；点名称可选，留空时按路线顺序自动命名。路线不自动规划道路。
- 路线点名称可以在点位列表中编辑；添加或撤销路线点时，未自定义名称会自动更新为起点、转折点或终点。重命名只更新显示，不会清除或重新请求该点的天气数据。
- 默认按累计距离约每 5 千米采样天气，可选约 2/10 千米或按点数采样；等距网格最多 61 点，长路线会增大间距，用户点选的转折点始终保留。模式云量和厚度图支持连续云区估算及仅采样点对照，绿色海拔线可上下拖动。
- 路线天气请求完成后可展开逐点数据诊断，单独复制或一次复制全部分析点的字段名、数组形状和能力状态，便于排查空图；摘要不含天气数值或坐标，剪贴板不可用时可手动复制。
- 路线剖面下方按先后顺序并排对照所有分析点的坐标、路线距离、地形与查询海拔、温度、湿度、风向风速、查询高度云量、直接云底和地面降水。点选卡片即可切换到该点垂直剖面；未读点与缺测值仍保留在列表中。
- 所有用户都能看到插件内置的贡嘎山、冷嘎措、子梅垭口、牛背山、卡瓦格博、南迦巴瓦、飞来寺和索松村。内置坐标已由奥维 GCJ‑02 转为 Windy 使用的 WGS‑84；贡嘎山、卡瓦格博和南迦巴瓦使用提供的校正海拔。个人收藏仍只保存在当前浏览器中。
- 分别读取路线地形和天气。地形采样除约 250 米间距的路线点外，还会精确纳入每个用户转折点；侧栏显示五位小数坐标及对应的 Windy 地形高度或缺测状态。全屏路线剖面以距离为横轴、海拔为纵轴，支持模式云量、云层厚度估算、湿度、温度、风速和高湿可能云区显示。模式云带与高湿可能云区分别标注来源；长路线采样可取消，取消时会终止尚未完成的 Windy 请求。地形采样密度不代表气象模式分辨率。
- 点击路线分析点可查看该点 0–9000 米的温度、湿度、风速和云量垂直曲线，以及对应高度层表格；拖动任一路线点曲线会同步路线查询高度。查询高度低于该点地形或缺测时，会显示最近有效层的温湿风云原值，并可一键把查询线移到该层。只有一个有效层或层间有缺测时，会把实际高度和值直接显示在图表上方，同时保留断线，不伪造趋势。沿线地面降水单独显示，不解释为高空降水。温度视图在各个实际天气分析点标出 0°C 温度层估算圆点；圆点之间不连成未经采样的连续冻结层。

## 数据边界

插件只使用 Windy 当前所选模型和 Windy 点预报/地形接口，不混用 ECMWF 与 ICON 字段，也不接入外部天气源。每个地点、模式和时刻可用的高度层不同；少于两个连续有效层时无法绘制趋势线，插件只显示已有点值和缺测原因。气象模式估算不等于现场实测。

插件只提供天气数据分析，不输出飞行安全或适飞结论。当前版本不提供 ECMWF/ICON 差异比较、预报动画、数据导出或外部报告。插件适合个人或小范围在 Windy 页面内使用。
